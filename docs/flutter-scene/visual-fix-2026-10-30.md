# 人物错位与轮廓边缘修复：scene-0.2.0-r3

用户反馈：r2 在苹果手机浏览器达到 50 FPS 以上，但四张截图显示白边、眼球和头发错位。此前仅凭桌面截图判断外观通过不充分。

## 改动与证据

- `Quaternion.rotated` 在当前 vector_math 中执行逆向旋转，和 Scene 的 Node 渲染矩阵方向不同。附属关节的位置现在使用同一主动旋转矩阵。真实 Storm 绑定测试在修复前首帧左眼偏移约 2.8 mm，修复后通过。
- Scene 可能在 GPU 完成时额外绘制；恢复附加姿态现在作为模型组件在每次 prepass 的动画前执行，程序姿态使用引擎本次 dt，避免叠加上次结果。
- 平铺骨骼不再分别平滑头部、眼球和头发的位置。头部平滑的矩阵差量统一作用于附属关节，眼球中心与发根另保持绑定锚点；保留原眼球朝向、发梢动画及弹簧摆动。测试涵盖交替左右转头、带偏移的插值输入、零 dt 额外绘制。
- 在色调映射后、FXAA 前，将预乘人物覆盖率和与 Flutter 相同的灰色渐变合成，最终向浏览器提供不透明画面。没有删减模型或表情通道。透明负对照和不透明输出均直接读取渲染图的 display_color 像素，统计见 `edge-coverage-probes.json`：不透明路径 921600 像素全部 alpha=255；透明路径有 533654 个 alpha=0 和 2901 个半透明像素。自适应渲染使两个捕获尺寸不同，这不是逐像素图像差分。

诊断用 `SCENE_DIAGNOSTICS=true` 构建才开放 probe、capture 和透明背景负对照；发布构建不带此 define，不执行读回或逐帧误差探针。

## 验证边界

23 项 Flutter 测试通过，含 341 个既有表演曲线采样。构建与线上核对另见 `web-verification.json`。真实模型的最终连续动作探针、画面与发布记录见 `visual-fix-verification.json`。

桌面浏览器没有完整复现手机白边；不透明合成已验证，但 Safari 上是否消除白边、r3 手机 FPS 和发热仍待用户原设备复测。没有本次 Android 包或真机麦克风验证。

复测入口仍为 https://49.233.179.83/scene/ 。手动刷新后在设置确认 r3，观察静止、左右转头、24 秒连续表演、情绪和课程切换；重点查看眼角、发根、轮廓白线与帧率。
